Markdown Syntax: The Complete Cheatsheet for Developers

From basic formatting to GFM tables and task lists — a comprehensive Markdown reference with examples you can copy and paste.

2026-05-16 9 min read Writing

Why Markdown?

Markdown is the universal writing format for developers. README files, documentation sites, blog posts, pull request descriptions, Slack messages — all Markdown. Once you know it, you'll use it every day.

Basic Formatting

**bold text**
*italic text*
~~strikethrough~~
`inline code`

# Heading 1
## Heading 2
### Heading 3

> Blockquote

--- (horizontal rule)

[Link text](https://example.com)

[Link with title](https://example.com "Title text")

GFM Extensions

GitHub Flavored Markdown adds:

  • Task lists: - [ ] todo
  • Tables: pipe-separated columns
  • Strikethrough: ~~deleted~~
  • Autolinks: URLs become clickable automatically
  • Code fencing: with syntax highlighting

Real-World Traps and How to Avoid Them

Markdown seems simple but has sharp edges that trip up even experienced developers:

  • Underscores in code: Inside inline code, underscores don't trigger emphasis. Outside, my_variable will render as myvariable in some renderers. Always use code formatting for identifiers with underscores.
  • Nested lists need 4 spaces: A sub-item under - Item needs 4 spaces (or 2 spaces in some renderers). Getting the indent wrong creates broken nesting or merges items incorrectly.
  • HTML inside fenced blocks: If you write <div> inside a fenced code block, it's safe. But if you indent HTML within a list item, some parsers treat it as real HTML and strip the indentation.
  • Trailing spaces and line breaks: Two trailing spaces create a hard line break in most renderers. Some platforms (notably GitHub) also treat a single newline as a line break in paragraphs, but not all — stick to two spaces when you need a hard break in portable Markdown.
  • Table alignment colons: |---|: (left) vs |:---|: (center) vs |:---| (right) — the colons only work in GFM. CommonMark renders them as left-aligned regardless.

Markdown in Popular Tools

Most developer tools use one of these parsers:

  • GitHub / GitLab — GFM with syntax highlighting via Linguist (100+ languages)
  • VS Code — Markdown + preview tab (uses markdown-it), supports GFM tables and task lists
  • Jekyll / Hugo — Kramdown (Ruby) and Goldmark (Go) respectively — subtle differences in how they handle block-level HTML inside list items
  • Notion / Obsidian — Both support callout blocks ([]() syntax) which are non-standard but increasingly common

When Markdown Isn't Enough

Markdown is a formatting language, not a layout language. If you need:

  • Complex tables with merged cells — use HTML inside Markdown (if your renderer allows it), or export to a different format
  • Footnotes — use MultiMarkdown or a tool like remark-footnotes (not in standard GFM)
  • Math equations — use LaTeX inside $$...$$ blocks with a KaTeX or MathJax renderer
  • Embedded diagrams — Mermaid (```mermaid) is widely supported in GitHub, GitLab, and VS Code
